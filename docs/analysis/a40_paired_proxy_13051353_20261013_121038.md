The proxy increased p95 TTFT on this one-GPU workload. The p95 E2E and
throughput intervals cross zero, so these five pairs do not resolve the sign
of those differences. The reported analysis flags latency comparison eligible:
there were no failed paired requests and no generated-token-count mismatches.
Seventeen of 500 paired request IDs produced different output text, so this
run does not establish byte-identical generation across routes.

## Interpretation and limits

This experiment measures **external proxy overhead** with one colocated vLLM
server on one A40. It does not deploy a second GPU pool, disaggregated
prefill/decode, KV transfer, or an adaptive controller. It therefore cannot
support a HeteroServe speedup claim. Prompt repetition creates mixed lengths
quickly but is synthetic and should not be treated as a production workload.
One-second `nvidia-smi` utilization samples, if collected, are occupancy
telemetry rather than kernel-efficiency measurements.

The capability path `results/raw/capabilities/real_gpu_final_13051353.json`
was reused by an earlier run in the same Slurm job, replacing the earlier
snapshot on Discovery. The earlier snapshot remains preserved in its first
transferred bundle. Future scripts now use a run-unique capability filename.
