# V100+A100 cross-node pool-routing results

**Evidence:** `real_gpu_final`, from the operator-supplied processed JSON for run
`hetero_v100_a100_20261013_132610`. The remote raw bundle has not yet been
copied to this checkout for independent hash recomputation. This report records
the supplied analysis exactly; it does not certify uninspected raw files.

## Deployment and workload

- V100-PCIE-32GB on `d14-06`, regular Slurm job `13065408`; A100-PCIE-40GB on
  `a01-01`, regular server job `13064933`; driver 580.159.04 on both.
- Two independent colocated vLLM 0.11.2 serving pools, one per GPU. Requests
  are routed between pools across nodes. There is no prefill/decode split and
  no inter-pool KV cache transfer.
- Qwen/Qwen2.5-0.5B-Instruct, model/tokenizer revision
  `7ae557604adf67be50417f59c2c2f167def9a775`, FP16. The runner requires
  matched model configuration and trace SHA across arms; see the remote index.
- Three matched repetitions for each of three policies, 100 measured requests
  per policy per repetition. Client concurrency 8. Warmups preceded measured
  runs. Declared SLOs: TTFT 1 s, TPOT 0.1 s, E2E 5 s.
- Remote index: `results/raw/hetero_v100_a100_20261013_132610/multiarm_index.json`.
  Remote processed JSON:
  `results/processed/hetero_v100_a100_20261013_132610.multiarm_analysis.json`.

## Measured client-side results

Values are the median of three run-level values. TTFT is client submission to
first streamed text, including client/router/server/network delays. E2E is
client submission to completion. Goodput is generated tokens per wall-clock
second meeting the **E2E** SLO; it equals throughput here because all measured
requests succeeded and met that bound. It is not TPOT-based SLA goodput.

| Policy | P95 TTFT | P95 E2E | Output throughput | E2E goodput | Success |
| --- | ---: | ---: | ---: | ---: | ---: |
| Round robin | 92.04 ms | 550.94 ms | 1,760.17 tokens/s | 1,760.17 tokens/s | 100% |
| Prompt threshold | 83.63 ms | 504.94 ms | 1,799.64 tokens/s | 1,799.64 tokens/s | 100% |
| Least active | 64.46 ms | 528.61 ms | 1,826.17 tokens/s | 1,826.17 tokens/s | 100% |

The paired delta is policy minus round robin, computed from matched run pairs.
The 95% bootstrap intervals use only three run-level pairs and are therefore
coarse; they should not be read as precise population bounds.

| Policy | P95 TTFT paired delta (95% CI) | P95 E2E paired delta (95% CI) | E2E goodput paired delta (95% CI) |
| --- | ---: | ---: | ---: |
| Prompt threshold | −8.41 ms (−10.23 to −5.71) | −46.01 ms (−49.87 to −44.83) | +41.22 tokens/s (+35.95 to +45.03) |
| Least active | −26.65 ms (−29.96 to −23.99) | −23.94 ms (−25.09 to −22.33) | +66.00 tokens/s (+43.92 to +66.17) |

Least active had the lowest P95 TTFT and highest E2E goodput; threshold had
the lowest P95 E2E. These findings apply to this trace, load, topology and
small model. Cross-node network time is included. The run is a real
heterogeneous *pool routing* comparison, not evidence for disaggregated
inference or the un-deployed adaptive DQA controller.

## Correctness and route counts

All 900 measured requests succeeded. Compared with round robin by request ID,
there were zero generated-token-count mismatches and 23 generated-text
mismatches across the other two policies. Thus matching token counts support
the latency comparison gate, but output text was not byte-identical. The cause
of text differences remains unverified and should be investigated before a
strong correctness or quality claim.

| --- | ---: | ---: |
| Round robin | 150 | 150 |
| Prompt threshold | 183 | 117 |
| Least active | 124 | 176 |
